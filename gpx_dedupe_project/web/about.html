几何去重原型 V0.1

少走重复的路，
先看清路线的结构。

GPX 路线实验室用于识别轨迹中的特定重复结构，并把处理结果与原轨迹放在一起核对。当前是有限范围的几何去重原型，不是任意道路去重器，也不是导航规划器。

原始处理后结构示意，非实测数据
当前能做什么读取本地文件夹中的 GPX；选择单条轨迹运行；识别闭环首尾往返尾巴和 2–6 圈重复整圈；并排或叠加检查；导出 GPX、GeoJSON、JSON 报告。源文件不会被修改。

这些路线，当前会怎样处理？

“理想目标”说明希望解决的问题；“当前能力”说明 V0.1 实际实现的边界。未支持的类型不应被当作已完成的功能。

技术路线：几何证据优先

不接入在线地图，不推测新道路。算法位于 route_dedupe.py，网页调用同一个处理入口，没有另写一套去重逻辑。

读取与本地投影

使用 ElementTree 解析 GPX 1.1。目前要求恰好一个轨迹段、至少 3 个轨迹点。通过 pyproj 投影到本地 UTM，以米度量距离。

等距采样与空间检索

按 10 米重新采样，使用 SciPy cKDTree 搜索空间近邻。默认匹配半径 18 米；候选重合比例只是证据，不是已确认的重复道路占比。

检查首尾往返尾巴

先确认首尾接近，再结合反向航向、沿程单调匹配与连续性检测重合。默认在全长的前 45% 与后 45% 中寻找连续反向匹配，允许重合段晚于起点出现、两侧接入路程不等。匹配至少 150 米，且须覆盖每侧待裁行程的至少 70%；程序调用可另设搜索距离上限。

检查全程重复整圈

未找到尾巴时，才在闭合路线中检测 2–6 圈全线周期匹配。要求各圈相位对应位置足够接近，不用于任意局部重复段。

保守裁剪与闭合

保留主体闭环或一圈。对应切点间距不超过 20 米才做中点拼接；超限保持原样。不确定时不猜测连接道路。

输出与人工核对

输出 GPX、GeoJSON 和 JSON 证据报告。网页用相同视野进行并排与叠加展示，支持缩放、坐标检查和文件下载。

输出是什么，不是什么

输出与报告

  • cleaned.gpx：处理后轨迹，可保留海拔，不保留时间戳。
  • cleaned.geojson：WGS84 经纬度 LineString，便于 GIS 工具继续处理。
  • report.json：处理方法、输入输出长度、点数、匹配参数、切点间距和闭合状态。
  • 网页每次运行生成独立输出目录，不覆盖源文件或上一次结果。命令行另外生成静态对比图。

理解这些边界

  • 尾巴裁剪会移除两侧接入行程，包括没有反向匹配证据的部分，并非保留全部唯一路段。网页与报告会列出匹配长度及未匹配裁剪行程估计。
  • 减少长度是轨迹行程减少，不等于重复道路长度；未匹配行程估计也不是已验证的独有道路长度。
  • 10–20 米的近邻可能是平行步道、不同车道或桥梁上下层。没有路网语义，无法保证同一道路。
  • 多轨迹段会被拒绝，避免把中断处连成不存在的道路；GPX 1.0、仅路线点的 GPX 暂不支持。
  • 网页是本机文件工具，只监听回环地址；不要作为公网服务部署。

下一阶段：从轨迹裁剪到道路图

以下为技术规划，不是当前可用的能力。

  1. 专用纯往返规则：验证 A → B → A 的折返点与匹配覆盖率，保留一个方向，而不是误用闭环尾巴裁剪。
  2. 任意位置的连续路段匹配：空间索引、线段方向及局部序列对齐，识别内部回头支路。
  3. 交点切分与唯一边聚类：使用 Shapely 切分真实交点，让同一道路的多次通过收敛到统一 edge_id。
  4. 图拓扑与输出策略：使用 NetworkX MultiGraph 区分“可连续行走的主路线”和“包含全部唯一路段的道路图”；两者不一定能同时满足无重复和连通。
  5. 路网与人工确认：对接 OSM / GraphHopper，区分平行道路、桥梁、立交，并给出不确定匹配证据供人工确认。
当前回归包括检测器检查，以及调用完整处理入口、检查 GPX / GeoJSON / 报告导出的合成用例：长尾巴、晚开始且不等长的接入行程、单圈、2 圈、纯往返、开放路线、8 字、半径外平行道路、过短重合、覆盖率不足和超限切点。另有可选的 37002172.gpx 真实文件测试，缺少私有样本时会跳过。这些用例不代表任意真实路网均已验证。
