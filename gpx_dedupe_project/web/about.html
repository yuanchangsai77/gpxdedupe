几何处理原型 V0.1

一条轨迹，
不止一种路线结构。

先分清路线的拓扑，再决定要保留什么。这里说明常见结构怎样识别、哪里容易出错、识别之后有哪些处理选择，以及 GPX 路线目前真正做到了哪一步。

理解拓扑结构总览逐类前后对比识别规则成功率与证据选择处理目标限制与规划
先说明边界目前只有首尾往返尾巴裁剪、完整同向重复圈合并两类变换。下文的拓扑分类是知识说明，不是软件已输出的分类结果；处理方式标为“规划”的尚无可操作按钮。真实路线成功概率尚未建立。

拓扑描述“怎样连接”，轨迹还记录“怎样走过”

将路口、起终点、折返点看成节点，将节点之间的道路看成边；轨迹则是按时间顺序经过这些边的记录。同一条边可能走一次、多次，方向也可能相反。

三个不同的问题

  • 几何重合：两个位置足够接近，可能来自同一道路，也可能是平行路或上下层。
  • 拓扑相连：道路真的能在该位置转向连接。画面上的交叉不一定是路口。
  • 通过次数：同一条边按什么顺序、什么方向走了几次。这决定哪些行程重复。

分类可以叠加，不是互斥菜单

一条路线可能是“长尾巴＋8 字双环＋内部支路”，也可能“先走两圈，再多走半圈”。下面列的是常见构件与组合，不是穷尽所有数学图结构。

当前程序不建立完整道路图，不会输出“这是 8 字、含 3 个分叉”之类的结构标签。它只尝试两个几何变换；unchanged 不是“已证明没有重复”。

常见结构：先看能否处理，再看识别难度

“相对难度”是在采样足够、定位误差较小、没有近邻歧义时的工程判断，不是测出来的概率。未实现的规则即使概念清楚，也不能算软件支持。

专用识别与处理：规划

识别思路：需要局部序列对齐和断点分段，把完整圈、残圈及方向分开，固定“全长÷圈数”不足以解决。现有规则仍可能命中其他变换，不能保证原样保留。

内部回头支路：删支路不等于保留全路网

内部支路去重：规划

识别思路：在任意沿程位置寻找 B→C 与 C→B 的反向连续匹配，再确认 B 是接入节点。当前没有任意位置支路检测，开放路线的这类重复尤其不会被处理。

规划：主路线 / 道路图A → B → D / AB、BC、BD

取舍：删掉往返 BC 两次，可保留连续主路线但丢掉 C；保留 BC 一次为道路图则不一定能按不重复的连续路线走完。嵌套支路与真实小环更难区分。

8 字与相接双环：交点不代表重复路段

当前：无拓扑重构

识别思路：识别交点、确认是否真实路口，按边的通过次数区别“双环各一次”与“某个环多次”。单一交叉点不构成可删的长重合段。

合理目标：两环都保留X → 左环 → X → 右环 → X

当前证据：已有合成 8 字保留测试，不代表已分类或所有真实交叉都安全。可规划分环导出、选主环或保留双环；若是桥上桥下，不能在交点合并节点。

共享路段、多环多分叉：需要完整道路图

边聚类与图求解：规划

识别思路：连续路段匹配后统一 edge_id，在真实路口切分，累计每条边的方向与次数，再分析分叉、桥边和环。当前程序没有这些数据结构。

处理前多次穿过公共走廊的有序轨迹
规划：两种独立输出连续主路线 / 完整唯一路网

为什么难：共享边可能被不同环以不同顺序经过；只选最近点会配错分支。完整路网不一定存在一条不重边的走法，应允许输出多条线，而非虚构连接。

平行路与立交：这是歧义，不是可靠去重证据

当前：仅几何阈值

识别思路：同向或反向近邻只能生成候选。物理道路身份需要路网连接、道路层级、桥隧标签或可信高程辅助；本项目尚未接入。

安全目标两条不同道路都保留

风险：间距大于 18 米的平行路较易被排除；小于阈值时仍可能误判。调大半径既提高容错，也增大误删风险；高程当前不参与识别。此类不能给出可信通用成功率。

断段与漂移：先修数据，再讨论拓扑

多段：拒绝；漂移清洗：规划

识别思路：检查段边界、时间间隔、速度突变和离群点，再决定分段还是滤波。当前网页有文件格式与坐标安全校验，但没有基于速度的清洗；输出也不保留时间戳。

边界：同一个 trkseg 内的大跳点不等于已被自动识别。不能因为画出了一条直线就认为有连接道路；跨多个 UTM 区或跨日期变更线也不在验证范围。

当前程序究竟怎样判定？

下面是已实现的规则，不是未来完整拓扑分类器。网页与命令行调用同一个 route_dedupe.py 入口。

读取、投影、采样

GPX 1.1，恰好一个 trkseg、至少 3 个点；以本地 UTM 投影计算米制距离，每 10 米重采样。海拔可输出，但不参与匹配。

先看闭合与近邻

首尾距离不超过 25 米才进入闭环变换。cKDTree 搜索近邻，默认匹配半径 18 米。overlap_candidates 只是非相邻样本的潜在近邻统计，不是道路重合率。

找连续反向匹配

搜索前 45% 与后 45%，方向点积 ≤ −0.55（约大于 123°）。反向沿程不回退，局部进度误差受限；允许约 70–80 米短缺口，再以连续段密度约束过滤。

筛选有效尾巴切点

匹配至少 150 米、段内密度至少 85%、覆盖两侧待裁行程各至少 70%。保留中段至少 450 米，排除近似镜像纯往返；切点间距 ≤20 米。末尾不合格时回看较早有效切点。

未命中才比较整圈

按 6 到 2 个周期尝试，总长÷圈数须至少 450 米。每圈取 151 个相位探针，90 分位偏差不超过匹配半径，匹配比例至少 85%；单圈切点也须满足 20 米拼接限制。

裁剪、拼接、报告

有效尾巴留中间，重复圈留首周期，切点用中点闭合；无符合项则原样。输出 GPX、GeoJSON、JSON，网页保留原轨迹供并排和叠加核对。不是道路级导航匹配。

70%、85% 都是规则阈值，不是成功概率。同样，候选重合比例、圈间匹配比例与切点距离都只是证据；当前没有经过校准的置信分数。网页只开放匹配半径，其他阈值不等于已经提供可视化设置。

成功概率：已知什么，尚不知道什么

真实路线的识别、误删及处理成功概率目前均未知。必须分别问“识别出结构没有”“处理对了没有”“有没有误删”。只统计命中次数，可能把错误合并也算成成功；只统计保持不变，又可能把漏检算成安全。

什么结构相对有利？

  • 较长、连续、方向清楚的公共尾巴，误差小于匹配半径，两侧覆盖率足够。
  • 完整、近似等长、同向的重复圈，每圈大于最小周期，整体 GPS 偏移较小。
  • 没有近距离自靠近的干净开放单程或单圈，目标只是保留时较简单。

什么结构不宜自动相信？

  • 短重合、漂移接近半径、急弯稀疏点、接入未匹配部分过多：容易漏检。
  • 细长小环、平行路、立交、多次交叉、共享走廊：容易混淆甚至误删。
  • 内部支路、混合方向、残圈、多环多分叉：当前缺专用规则，不应承诺处理成功。

评测如何判分、怎样复现？

正确处理：保留类要求 method＝unchanged 且输入输出坐标数组完全相同；裁切类还须方法、圈数正确、严格闭合，与目标环的双向采样距离 ≤30 米，长度差 ≤max(60 米, 5%)。参考长度取原始带噪单圈 / 中间环的观测长度，不要求未实现的去噪。

怎样才能得到可信的真实成功率？
  1. 按拓扑、设备、城市/山地、漂移等级分层收集样本，并由人工结合路网标注真值。
  2. 区分可识别目标、应保持样本、应拒绝样本；不能把所有 unchanged 当作识别正确。
  3. 分别统计识别召回率、识别精确率、误删率、漏删率，以及处理后长度和边覆盖误差。
  4. 调参数据与独立测试集分离，报告每类分子/分母、参数、置信区间，披露失败样本。
  5. 再评估“主环提取”“单程保留”“唯一边覆盖”“可行走连通性”的各自成功率，不把不同目标混算。

目前尚未建立这套真实基准，所以真实识别概率、误删概率和处理成功概率均为未知。

先选目标：少重复、全覆盖、连续走，不总能兼得

保留原始轨迹

不改变行程和覆盖范围，适合有歧义时人工核对。当前源文件始终只读；导出文件不保留原时间戳，不等于原文件的逐字节副本。

提取主体闭环 / 一圈 当前

便于拿到一条较短的闭合路线；代价是改变起终点、可能失去尾巴或独有接入路。当前没有“只删有重复证据的部分”这一安全保证。

纯往返保留单程 规划

保留一个方向，减少一半重复行程，但不再回到原起点。去程和回程有差异时，还需决定选哪条或怎样融合。

保留全部唯一道路 规划

输出去重边集合或多条 LineString，保留支路与所有真环；这是路网，不一定是一条可直接导航的有序轨迹。

生成连续可走路线 规划

需要道路连接与通行约束。无向连通图只有 0 或 2 个奇度节点时才存在一笔不重边走法，闭合走法需 0 个；带方向、禁行或不连通路网还更复杂。有些重复是全覆盖必需的，不能靠删点消除。

使用限制与下一步

现在可用

  • 本机文件夹读取、搜索、选择单条 GPX，默认不递归；可包含子目录。
  • 并排 / 叠加、同步缩放平移、图层切换、坐标表、证据报告。
  • 下载 GPX、GeoJSON、JSON；每次运行独立目录，不覆盖源文件。CLI 另有静态对比图。
  • 离线几何视图，没有在线底图或道路导航；服务只监听回环地址，不用于公网、多用户部署。
