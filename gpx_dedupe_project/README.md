# GPX Route Deduper V0.1

一个可执行、有限范围的 GPX 轨迹几何分析原型。

## 环结构识别（独立只读入口）

网页默认进入「环结构识别」；原有 P0 候选转换在独立模式保留。识别不裁切、不去重、不调整原始坐标，也不会生成 cleaned GPX。

- **整体闭合 ≠ 有环**：`report.whole_track` 只表示首尾距离，`has_loops` 独立表达几何环（`true` / `false` / `null` 未知）。纯往返可以整体闭合而没有环。
- 采用有界、确定性的**连续原始行程识别**（报告 `schema_version="2.1"`）：8 字可分成两个连续叶瓣，同一简单环重复跑记为一个环及多次 `occurrences`，方向相对第一次经过。不是枚举所有组合环，也不是物理道路图重构。
- `loops` 为通过当前几何检查的**简单环**，`loop_candidates` 为尚待核对的简单环假设。`closed_walks` 独立记录含折返或子环的**完整闭合行程**，不计入简单环数，也不单独将 `has_loops` 设为 true。例如 `A→B→C→D→C→E→A` 保留全部行程，可标为含折返的闭合行程；绝不删除 `CDC` 后把 `ABCEA` 认作实际发生的简单环。
- 每次经过记录原始边索引、边内比例 `t` 和累计里程；**只能有一个连续的 `source_intervals`，`excluded_intervals` 必须为空，长度等于区间的全部原始里程差**。地图完整高亮该区间，不省略内部折返。旧版多段拼接报告不符合新定义，应重新识别；历史文件不会改写。
- 可识别已知完整简单环的连续片段为 `status=partial`，不补闭合线；遇到内部支路或来源断点时分开记录，不能拼成一次经过。尚非任意位置残圈/混合结构的完整匹配器。
- **几何环不等于确定路口连通**：二维交叉、空间近邻与相似形状不能证明同一道路。窄环、低于分辨率或仅插值交叉支持的简单环为候选；频繁小尺度反转会保守标记噪声未知，仍不能保证检出所有 GPS 漂移。
- 默认间距 8m、匹配半径 12m，实际回访半径 `min(匹配半径, 0.75×间距)`、最小环周长 80m、可分辨宽度 24m。增大匹配半径不会无限扩大回访半径。结果 `resolution` 明示实际阈值；没有检出不代表不存在小于这些尺度的环。
- 限制：单 `trkseg`、局部 UTM（不支持跨日期变更线/大跨度/极区）；16MiB、50,000 原始点、12,000 分析点。空间候选/交叉候选、图边、环及经过数量有独立上限。输入/采样准入失败明确报错；检索超限返回 `completeness=partial` 与诊断，不声称找全。`complete` 只表示此次有界顺序分解完成，不代表找全数学环或实际道路。

### 2.1 全程摘要与精确折返注释

报告新增 `route_summary` 和 `retrace_annotations`。主结论先说明完整原始行程的长度及首尾闭合事实，再说明检出的精确反向复走，严格简单环数独立展示。例如本机 `34044351.gpx`：全程约4.257km，原始零基点80→82→84构成PQRQP折返，往返约44.42m、占1.04%；仍完整保留全部原始行程，不生成删去折返的简单环。

精确注释只识别**原始经纬度顶点的精确反向序列**，分析时跳过连续零长度重复点并保留原始索引。不同去回采样密度、部分边重合、噪声及不形成精确回文的复杂结构不承诺检出；“未检出”不能写成“没有折返”。精确只描述记录坐标，不验证物理道路身份。原有采样回访证据仍保留，不把48m采样窗口当44.42m精确值重复计量。

注释长度按原始累计里程计算，总量按来源区间并集统计，不双计嵌套/重叠行程。“短折返”仅为描述标签：单次往返≤100m、≤全程5%，且非全程本身；不改变简单环判断、不删除轨迹。纯往返若精确反向序列覆盖全程，单独说明整段精确反向重走，不标为局部短折返。首尾精确相同、容差内接近和开放明确区分；这些都不证明去除折返后的主体为环。

注释扫描比较预算独立复用 `max_spatial_pairs`，输出数量上限复用 `max_occurrences`；超限时 `route_summary.annotation_status=partial`，不改严格层的 `completeness`。注释层complete只表示限定精确序列扫描完成，不保证找全真实折返。页面接受旧2.0但明确提示缺少折返测量，不能把缺字段当零；2.1缺少或包含无效测量字段则拒绝显示，历史报告不会改写。

Python API（`loop_recognition.py`）：`recognize_loops(path, config=None)` / `recognize_bytes(raw, config=None, source_name='track.gpx')` 返回 JSON 兼容对象，本身不写文件、不调用 legacy 裁切或 plans。`POST /api/recognize-loops` 接受 `{file_id, radius}`，只注册识别报告下载；不能把识别 ID 交给 `/api/apply` 执行转换。

### 单文件独立运行

只需复制 `loop_recognition.py` 到任意目录，无需本仓库其他脚本、网页、配置或默认 GPX 目录。运行环境为 **Python 3.10+**，直接依赖仅 **NumPy、SciPy、pyproj**；不是零依赖可执行程序。它不导入 `route_dedupe.py`、`route_plans.py`、Web 服务或 matplotlib。网页继续调用同一识别模块，报告2.1与识别规则保持不变。

在目标环境一次性安装依赖（联网安装，脚本本身不下载依赖）：

```bash
python -m pip install "numpy>=2.0,<3" "scipy>=1.14,<2" "pyproj>=3.7,<4"
```

把 GPX 保存在数据目录，脚本保存在可信目录，然后传入路径：

```bash
python loop_recognition.py "D:/data/路线.gpx"
python loop_recognition.py "D:/data/路线.gpx" --out "D:/results/recognition.json"
python loop_recognition.py "D:/data/路线.gpx" --radius 12 --spacing 8
```

不加 `--out` 时完整JSON写到标准输出；加上后只创建一个不存在的UTF-8报告文件，父目录需已存在，不覆盖原GPX或已有文件。成功退出0，非法参数/输入/输出失败退出2；计算预算不足可能成功返回带partial诊断的报告，需要检查报告而不是只看退出码。Windows管道如需统一UTF-8，可用 `python -X utf8 loop_recognition.py ...`。

同目录Python代码也可 `from loop_recognition import recognize_loops` 调用。单文件独立不代表可直接绕过Python隔离模式的导入搜索规则：`python -I loop_recognition.py input.gpx` 可以直接运行，但 `-I -c "import loop_recognition"` 不会自动搜索当前目录。

自动化保证位于 `tests/test_standalone_recognition.py`：只复制这一脚本到临时空目录、移除PYTHONPATH、使用 `-I -B` 隔离进程，主动阻止旧项目/绘图库导入，对比19个合成样本完整JSON，并检查中文路径、标准输出、报告写入、拒绝覆盖、错误退出和输入哈希不变。未创建cleaned轨迹。未来若新增项目文件依赖，隔离测试必须失败。

在仓库内运行基准：

```bash
python tests/benchmark_loops.py
python -m unittest discover -s tests -p "test_standalone_recognition.py" -v
```

识别基准是独立的无噪声合成集合，标准输出含逐类环数/经过数、来源边界误差、未知与错误；不是后文 352 个 legacy 样本的替代，也不代表真实道路准确率。识别测试位于 `tests/test_loop_recognition.py`；浏览器拦截测试为 `tests/browser_loops.cjs`。共享走廊目前只有几何接触关系，不提供可信共享道路 ID；自动噪声估计、完整连续走廊匹配和真实道路身份仍未完成。

## P0 已落地范围

- 网页默认仅分析，候选未确认前只提供 JSON 分析报告，不发布转换 GPX/GeoJSON。候选预览不代表已保存结果。
- 现有尾巴/重复圈算法被封装为 `route_plans.analyze()` 候选生成器，`route_plans.apply()` 重新核验输入 SHA-256、完整分析、处理目标、计划摘要与严格布尔确认；主体环额外要求同意删除接入行程。已阻止候选不能确认转换。
- HTTP `POST /api/analyze` 与 `/api/apply` 分离；旧 `/api/run` 为仅分析别名。确认后生成 GPX、GeoJSON、报告、manifest；服务端临时目录准备完成后才原子发布并注册下载。
- 变更源文件、选择/参数或计划后须重新分析。待确认分析内存最多 8 份、有效期 30 分钟，服务重启失效；报告制品目前不会随分析过期自动清理，磁盘配额/持久作业/进程硬内存与超时限制仍未实现。
- 新增保守几何阻止规则，不是可靠道路身份判定；后文 352 样本表仍是 **legacy 原算法基线**，不表示 P0 包装器已达到某个成功率。纯往返单程、图重构、复杂组合和地图约束仍未实现。

下文 `route_dedupe.py` / `run()` 保留为 legacy 基线和兼容入口，直接调用仍会裁切并输出 `cleaned.gpx`、`cleaned.geojson`、`comparison.png`、`report.json`，**不经过网页确认保护**。不要将它作为 P0 安全执行 API。

## 算法

1. `xml.etree.ElementTree` 读取 GPX (当前限定恰好一段 `trkseg`)；采用 UTM 本地投影以米计算。
2. 每 10 米重新采样，在全程前 45% 和后 45% 中用 `cKDTree` 搜索空间近邻。可通过 `Config.max_tail_m` 额外限制每侧搜索距离，默认不设绝对距离上限。
3. 结合距离、反向航向和局部沿程单调匹配寻找持续重合，允许重合晚于起点出现、两侧接入行程不等。默认重合至少 150m，连续段匹配密度至少 85%，且匹配长度至少覆盖每侧待裁行程的 70%。这些是几何启发式，不是道路身份或交叉安全保证。
4. 符合条件后保留中间主体闭环，**裁掉两侧整个接入行程，包括未匹配部分**，不是只删一次重复通过，也不保证保留全部唯一路段。切点间距不超过 20m 才允许中点闭合。
5. 未发现尾巴时，检测 2–6 圈同方向、完整、近似等长的全线周期匹配。默认单圈至少 450m，因此标准 400m 跑道重复圈不在默认支持范围。
6. 没有满足规则时保持原样，不代表不存在重叠；内部回头支路没有专用处理。近似对称纯往返有保留保护，但没有“自动保留单程”能力。

### 本机样本与效果边界

`34044834.gpx` 的先前实测：46.204km / 1044 点 → 44.166km / 1008 点，首尾切点约 16m 偏差以中点拼接。这只是单个样本，不是普遍去重准确率，也不是道路导航级地图匹配。

`37002172.gpx` 暴露了旧规则的问题：从起点开始的短暂不匹配、2.5km 搜索上限和两侧路程对称要求，都会阻断后续持续重合的识别。现在用局部连续匹配与覆盖率约束处理此结构。报告中的 `prefix_matched_m` 是一侧匹配长度估计，`unmatched_access_m` 是两侧被裁行程中缺少反向匹配证据的长度估计，不能当成已验证的独有道路长度。

### 回归覆盖

`tests/test_route_dedupe.py` 包含原有检测器检查，以及完整处理与导出检查：长尾巴、较晚开始且两侧不等长的接入行程、单圈、2 圈、开放路线、纯往返、8 字、半径外平行道路、过短重合、覆盖率不足、切点超限。可选真实样本测试需要 `examples/37002172.gpx`，缺少私有文件时跳过。合成测试通过不代表任意 GPS 漂移、立交或路网拓扑均已验证。

### 已知限制

- 不支持把任意多分叉、多次交叉或重叠支路拆成无重复道路图；该问题需要独立的路段级匹配、交点切分与图重构模块。
- 不能跨越单个 GPX 的多个轨迹段：直接合并可能跨越轨迹中断、产生虚构道路。
- 缺少道路平行线和道路等级语义，约 10–20m 的 GPS 近邻可能是不同物理道路。导航前需对接地图匹配/路网校验。
- 一次标准闭环不应该被删除。重复整圈判定只在全线近似周期重复时启动。
- 处理后的 GPX 不保留原始时间戳（裁剪、重定位后原始时间语义不再成立）；可保留原有海拔。
- 压缩长度指实际运动轨迹长度减少，不代表删去了 2km 独有的道路几何。

## 路线拓扑、处理目标与成功比例

完整的逐类说明见本地 `/about`：包含 12 类结构、识别依据、难点、当前行为与处理前后示意。结构可以叠加，不是软件已经实现的 12 个分类器。

| 结构 | 识别依据与难点 | 当前 / 规划处理及前后对比 |
|---|---|---|
| 开放单程 | 端点分离容易检查，不代表内部无重复 | 当前无规则命中则 `A→B→C` 不变 |
| 简单闭环 | 闭合不等于简单环，需要排查重复边 | 当前普通 `A→B→C→A` 保留 |
| 纯往返 | 折返点两侧反向对齐，噪声会破坏对称 | 当前尝试安全保留 `A→B→A`；规划取 `A→B`，会改变终点 |
| 尾巴＋环 | 首尾持续反向重合、覆盖率充分 | 当前 `S→A→环→A→S` 变成 `A→环→A`，接入道路被移除 |
| 不等长接入＋环 | 重合开始较晚，局部进度一致但整体不对称 | 当前覆盖率达标可取中间环；未匹配接入也可能一起被裁 |
| 完整同向重复圈 | 2–6 个近似等长周期、相位坐标一致 | 当前 `环×k` 目标变成一圈；圈数可能误计，标准 400 米不在支持范围 |
| 残圈 / 混向圈 | 固定周期假设失效，需要局部对齐分段 | 专用处理未实现；规划分别保留完整环和残段，不保证当前原样 |
| 内部回头支路 | 任意位置持续反向匹配，区分支路与真环 | 规划 `A→B→C→B→D` 取 `A→B→D` 或保留 AB、BC、BD 道路图；当前未去重 |
| 8 字 / 相接双环 | 交点需验证为真实路口，不能把点交叉当重复边 | 当前有保留样本；规划保留双环、分环导出或按目标选主环 |
| 共享走廊 / 多分叉 | 边聚类、交点切分、通过次数；存在多解 | 规划分别输出连续主路线与完整唯一路网，当前未实现 |
| 平行路 / 立交 | 几何近邻不足以证明同一道路，需要路网语义 | 安全目标是保留不同道路；当前可能误裁 |
| 断点 / 多段 / 漂移 | 先检查段边界和数据质量，不能虚构连接 | 多 trkseg 当前拒绝；单段异常点清洗与分段处理未实现 |

主环提取、单程保留、全部唯一边覆盖、连续可导航路线是不同目标。比如树形支路要走到尽头再回来，重复通常不可避免；不能同时保证全覆盖、闭合、绝不重边。当前仅提供两类几何裁剪候选；P0 已增加与候选对应的主体环/一圈目标选择和确认，但没有通用多目标规划或路网重构。

### 352 个确定性合成样本的实测（不是实际 GPS 成功概率）

默认 Config；每个几何变体 × 每轴独立高斯扰动 σ=0/1/3/8 米 × 两个固定种子（1729、104729）。端点同样扰动；0 米两个种子是重复对照，不能当作独立实测。没有时间相关 GPS 漂移、真实标注集、置信区间；不要混合类别报总体准确率。

| 样本族 | n | 正类识别正确 | 处理符合目标 |
