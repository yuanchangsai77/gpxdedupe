# GPX Route Deduper V0.1

一个可执行、有限范围的 GPX 轨迹几何分析原型。

## 环结构识别（独立只读入口）

网页默认进入「环结构识别」；原有 P0 候选转换在独立模式保留。识别不裁切、不去重、不调整原始坐标，也不会生成 cleaned GPX。

- **整体闭合 ≠ 有环**：`report.whole_track` 只表示首尾距离，`has_loops` 独立表达几何环（`true` / `false` / `null` 未知）。纯往返可以整体闭合而没有环。
- 采用有界、确定性的**连续原始行程识别**（报告 `schema_version="2.1"`）：8 字可分成两个连续叶瓣，同一简单环重复跑记为一个环及多次 `occurrences`，方向相对第一次经过。不是枚举所有组合环，也不是物理道路图重构。
- `loops` 为通过当前几何检查的**简单环**，`loop_candidates` 为尚待核对的简单环假设。`closed_walks` 独立记录含折返或子环的**完整闭合行程**，不计入简单环数，也不单独将 `has_loops` 设为 true。例如 `A→B→C→D→C→E→A` 保留全部行程，可标为含折返的闭合行程；绝不删除 `CDC` 后把 `ABCEA` 认作实际发生的简单环。
- 每次经过记录原始边索引、边内比例 `t` 和累计里程；**只能有一个连续的 `source_intervals`，`excluded_intervals` 必须为空，长度等于区间的全部原始里程差**。地图完整高亮该区间，不省略内部折返。旧版多段拼接报告不符合新定义，应重新识别；历史文件不会改写。
- 可识别已知完整简单环的连续片段为 `status=partial`，不补闭合线；遇到内部支路或来源断点时分开记录，不能拼成一次经过。尚非任意位置残圈/混合结构的完整匹配器。
- **几何环不等于确定路口连通**：二维交叉、空间近邻与相似形状不能证明同一道路。窄环、低于分辨率或仅插值交叉支持的简单环为候选；频繁小尺度反转会保守标记噪声未知，仍不能保证检出所有 GPS 漂移。
- 默认间距 8m、匹配半径 12m，实际回访半径 `min(匹配半径, 0.75×间距)`、最小环周长 80m、可分辨宽度 24m。增大匹配半径不会无限扩大回访半径。结果 `resolution` 明示实际阈值；没有检出不代表不存在小于这些尺度的环。
- 限制：单 `trkseg`（无轨迹段时支持单 `rte`）、局部 UTM（不支持跨日期变更线/大跨度/极区）；16MiB、50,000 原始点、12,000 分析点。空间候选/交叉候选、图边、环及经过数量有独立上限。输入/采样准入失败明确报错；检索超限返回 `completeness=partial` 与诊断，不声称找全。`complete` 只表示此次有界顺序分解完成，不代表找全数学环或实际道路。

### 2.1 全程摘要与精确折返注释

报告新增 `route_summary` 和 `retrace_annotations`。主结论先说明完整原始行程的长度及首尾闭合事实，再说明检出的精确反向复走，严格简单环数独立展示。例如本机 `34044351.gpx`：全程约4.257km，原始零基点80→82→84构成PQRQP折返，往返约44.42m、占1.04%；仍完整保留全部原始行程，不生成删去折返的简单环。

精确注释只识别**原始经纬度顶点的精确反向序列**，分析时跳过连续零长度重复点并保留原始索引。不同去回采样密度、部分边重合、噪声及不形成精确回文的复杂结构不承诺检出；“未检出”不能写成“没有折返”。精确只描述记录坐标，不验证物理道路身份。原有采样回访证据仍保留，不把48m采样窗口当44.42m精确值重复计量。

注释长度按原始累计里程计算，总量按来源区间并集统计，不双计嵌套/重叠行程。“短折返”仅为描述标签：单次往返≤100m、≤全程5%，且非全程本身；不改变简单环判断、不删除轨迹。纯往返若精确反向序列覆盖全程，单独说明整段精确反向重走，不标为局部短折返。首尾精确相同、容差内接近和开放明确区分；这些都不证明去除折返后的主体为环。

注释扫描比较预算独立复用 `max_spatial_pairs`，输出数量上限复用 `max_occurrences`；超限时 `route_summary.annotation_status=partial`，不改严格层的 `completeness`。注释层complete只表示限定精确序列扫描完成，不保证找全真实折返。页面接受旧2.0但明确提示缺少折返测量，不能把缺字段当零；2.1缺少或包含无效测量字段则拒绝显示，历史报告不会改写。

Python API（`loop_recognition.py`）：`recognize_loops(path, config=None)` / `recognize_bytes(raw, config=None, source_name='track.gpx')` 返回 JSON 兼容对象，本身不写文件、不调用 legacy 裁切或 plans。`POST /api/recognize-loops` 接受 `{file_id, radius}`，只注册识别报告下载；不能把识别 ID 交给 `/api/apply` 执行转换。

### 单文件独立运行

只需复制 `loop_recognition.py` 到任意目录，无需本仓库其他脚本、网页、配置或默认 GPX 目录。运行环境为 **Python 3.10+**，直接依赖仅 **NumPy、SciPy、pyproj**；不是零依赖可执行程序。它不导入 `route_dedupe.py`、`route_plans.py`、Web 服务或 matplotlib。网页继续调用同一识别模块，报告2.1与识别规则保持不变。

在目标环境一次性安装依赖（联网安装，脚本本身不下载依赖）：

```bash
python -m pip install "numpy>=2.0,<3" "scipy>=1.14,<2" "pyproj>=3.7,<4"
```

把 GPX 保存在数据目录，脚本保存在可信目录，然后传入路径：

```bash
python loop_recognition.py "D:/data/路线.gpx"
python loop_recognition.py "D:/data/路线.gpx" --out "D:/results/recognition.json"
python loop_recognition.py "D:/data/路线.gpx" --radius 12 --spacing 8
```

不加 `--out` 时完整JSON写到标准输出；加上后只创建一个不存在的UTF-8报告文件，父目录需已存在，不覆盖原GPX或已有文件。成功退出0，非法参数/输入/输出失败退出2；计算预算不足可能成功返回带partial诊断的报告，需要检查报告而不是只看退出码。Windows管道如需统一UTF-8，可用 `python -X utf8 loop_recognition.py ...`。

同目录Python代码也可 `from loop_recognition import recognize_loops` 调用。单文件独立不代表可直接绕过Python隔离模式的导入搜索规则：`python -I loop_recognition.py input.gpx` 可以直接运行，但 `-I -c "import loop_recognition"` 不会自动搜索当前目录。

自动化保证位于 `tests/test_standalone_recognition.py`：只复制这一脚本到临时空目录、移除PYTHONPATH、使用 `-I -B` 隔离进程，主动阻止旧项目/绘图库导入，对比19个合成样本完整JSON，并检查中文路径、标准输出、报告写入、拒绝覆盖、错误退出和输入哈希不变。未创建cleaned轨迹。未来若新增项目文件依赖，隔离测试必须失败。

在仓库内运行基准：

```bash
python tests/benchmark_loops.py
python -m unittest discover -s tests -p "test_standalone_recognition.py" -v
```

识别基准是独立的无噪声合成集合，标准输出含逐类环数/经过数、来源边界误差、未知与错误；不是后文 352 个 legacy 样本的替代，也不代表真实道路准确率。识别测试位于 `tests/test_loop_recognition.py`；浏览器拦截测试为 `tests/browser_loops.cjs`。共享走廊目前只有几何接触关系，不提供可信共享道路 ID；自动噪声估计、完整连续走廊匹配和真实道路身份仍未完成。

## 整体路线形态四分类（单文件CLI）

网页默认使用路线类型识别。选择 GPX 或 TopRoute JSON 中的一条路线，点击「识别路线类型」，即可查看类别、理由并下载 JSON 报告。命令行使用 **`--classify`** 识别整条 GPX 路线。

在网页选中路线后，可从「路线标注」工具栏选择一个人工标签。再次选择会覆盖当前标签，也可取消标注。「管理标签」支持按路线名、来源或标签筛选和修改。标注存于服务输出目录的 `route-labels.sqlite3`，刷新网页或重启服务后仍可读取。人工标注采用 4 个大类和 12 个二级类型，编号与下表的算法输出独立。第 4 类包括多环组合、环内穿插和混合复杂。没有显著环的纯分叉或树形路线归入复杂游走，单个主环带简单尾巴归入长尾 Q 或短尾 Q。旧版标注无法直接对应新分类时保留为「待复核」，可在管理页重新选择。

人工标签 **3-1 单环型**按整体环状轮廓判断，涵盖闭合和近闭合路线，允许局部轻微折返、绕行和不规则形状。

| category | label | 含义 |
|---|---|---|
| 1 | 识别失败 | 输入无效、不支持、预算超限、噪声或几何解释不稳定，附`reason_code` |
| 2 | 环 | 单一主导O/Q形闭合主体，允许次要接入柄、支路及短折返 |
| 3 | 非环 | 线状、走廊、往返主导，或局部环分散、不构成主导整体 |
| 4 | 非标准环 | 闭合/多环明显，但有显著次环、内部弦/枝干，不能概括为单一O/Q；相近双环归此类 |

```bash
python loop_recognition.py "D:/data/路线.gpx" --classify
python loop_recognition.py "D:/data/路线.gpx" --classify --out "D:/results/shape.json"
```

紧凑JSON包含`kind=route_shape_classification`、`category`、`label`、`status`、`method=overall_route_shape_v1`、`reasons`、`metrics`及实际`config`。成功2/3/4退出0；类别1也输出结构化JSON（可保存报告），退出2；配置错误或输出失败退出2且走命令行错误提示。`--radius`、`--spacing`仅用于旧详细识别，不接受与`--classify`混用。Python调用：

```python
from loop_recognition import classify_route, classify_route_bytes, RouteShapeConfig
result = classify_route("D:/data/路线.gpx")
print(result["category"], result["label"], result["reasons"])
```

算法使用内部**观测几何图**，不输出删枝后的路线或声称它实际连续走过：相同原始坐标建立身份，数值容差内的顶点在线段上细分，合并同一无向边，按迭代双连通块/桥接结构计算宏观闭合部分和边界。联合主导边界比例、显著次环、内部弦/内向枝干、桥接走廊及分散环块判断；同时报告唯一路段与实际经过里程两套比例。长度重复经过不膨胀视觉骨架，不用圆度惩罚不规则环。

默认主导边界占唯一路段至少60%、显著次环门槛15%、内部结构门槛12%；非环走廊规则同时考虑总环份额、主环份额、桥接与次环比例，不是一个环占比阈值。类别4必须有显著次环、内部弦或内向枝干证据，单个环加外柄落在2/3边界时返回1，不以4兜底。原始线段细分容差默认0.05m，在0.025/0.05/0.1m复核类别稳定性。全部阈值与实际指标在结果中可查，不表示校准的概率置信度。

为避免采样密度改变判断，内部视图先有界归一化度为2、通过次数一致的近共线链，保留实际拐角和路口。交叉影响使用交点两侧默认40m物理邻域，不再把相交整条长边计为影响范围；共享端点的近邻边仅豁免12m节点邻域，长臂仍检查持续接近。无法分辨的窄三角/偏移往返返回1。明显双叶自交可在**视觉交叉切分假设**下判4，报告`visual_crossing_hypothesis`；该假设不证明实际道路可转向，也不生成真实经过记录。

整体近闭合单独检查首尾间距（默认同时≤25m和全程1%）、实际端点身份和端部方向。端点在内部重复出现时对正反方向一致拒判；同时核查走廊细分后的端点度数。符合条件时在内部副本将两个独立端点对称归到中点，报告`near_closure_assumed`与原始`endpoint_gap_m`，不再只移动末次观测。差1m的普通方环可以判2；反向近返回不能仅靠端点接近认证成环，必要时返回1。原始GPX、旧严格环及2.1详细报告完全不变。

细分连接必须有同走廊的共线邻边支持，单侧采样点落在另一条路线上不能升级为已观测路口。角点落在另一边内部也计入视觉交叉证据；节点存在两组独立直穿方向时，无论是否附加短支路，都保留几何交叉假设身份，不能以度数不等于4绕过保护。普通环链选取几何角点归一化起点，交叉40m邻域遇到人工共线分段时沿唯一连续物理链传播，避免循环改起点截断计量。近邻走廊按横距在12m内的**局部区间**裁切，并做节点邻域扣除与区间并集，不能因远端超宽而漏掉近端长窄段。归一化后无剩余边的低分辨率退化输入返回结构化类别1，不向调用者抛出数组索引异常。

视觉切分产生的闭合主体不得直接支撑类别2：`independent_ring_evidence`要求去掉推导交叉相关边后仍有占主导的独立闭合证据。明显宏观双叶可以判4；其余依赖交叉推导的O/Q解释返回1，不因路线放大或交叉占比变小而放行。

**支持边界：**当前v1优先处理规划路线中精确重复的观测身份与同折线不同顶点密度；尚未实现通用带GPS漂移的持续走廊匹配。不按12m半径把道路合并，不把视觉交叉假设认证为路口。少量局部交叉/近邻保留未核实说明；显著近邻走廊（默认超过20%）或无法作宏观双叶解释的显著交叉（超过5%）、多尺度不稳定解释返回1。这不是可靠物理路网认证，也不保证任意“肉眼像环”的输入都能判断。单轨迹段或单路线、16MiB、50,000点限制沿用安全输入层，图细分候选、共线链归一化、几何核查、视觉交叉去重、边及边界操作各有上限，超限返回1而不是把局部结果当完整分类。无需旧严格检测器的12,000采样点预算，但仍不是硬进程内存/超时隔离。

用户52条整体标签保存在`tests/route_shape_labels.json`，只由评测读取，分类器不读取文件名清单、不根据名称/哈希/地理位置判类。第二轮正确性修复后的开发验收为**47条匹配、5条因交叉证据不足返回1**（31622615、37000394、37002172预期2；37000114、37002374预期3）。没有将它们强行改成4，也没有为维持52/52而关闭保护；后续需人工核对，当前不能宣称覆盖全部标注。此前52/52只是旧规则的开发集结果。全部52条在划分前已观察过初步拓扑统计，其中8条后续未用于规则校准，但不能称为未见测试集或独立真实准确率。未标注的14572134和37000080不计分。评测保留失败、错误、缺失及不匹配，不从分母静默删除。

## 多路线导出JSON / NDJSON（单文件CLI）

同一个 `loop_recognition.py` 还支持按 `topRouteId`、原始序号或全部记录，对导出中的多条路线逐条作**整体四分类**。JSON模式自动启用分类，不返回旧详细2.1报告，也不会把多条路线连起来。

已检查的 `toproute_all.export.json` 实际为NDJSON（一行一个对象）：916条路线、131,134点，ID为唯一字符串。脚本不依赖该私有文件；支持同schema的NDJSON、顶层JSON数组及单路线对象。坐标只读取 `segments[0].routePoints[].longitude/latitude` 和可选 `altitude`，不以centerPoint代替路线、不猜经纬顺序；多segment暂返回该条类别1，不跨段补线。

```powershell
# 单条：ID精确字符串匹配，不提示批量确认
python loop_recognition.py "C:\Users\7281\Downloads\toproute_all.export.json" --top-route-id "实际ID"

# 从第10条开始取20条，即原文件第10～29条（1基，不按ID排序）
python loop_recognition.py "C:\Users\7281\Downloads\toproute_all.export.json" --start 10 --count 20 --out batch.json

# 全部：正式执行前仍需输入Yes
python loop_recognition.py "C:\Users\7281\Downloads\toproute_all.export.json" --all --out all-results.json
```

三个选择方式互斥，`--start`与`--count`必须同时提供，越界不静默截断；没有选择器也不会自动运行all。ID保留前导零，不将数字与字符串ID混为一谈；按ID遇重复或未找到拒绝选择。范围/all按index保留所有记录，缺失/非法/重复ID附warning，不以ID去重丢路线。`--input-format auto|gpx|json|ndjson`可显式指定；`.json`自动识别NDJSON，`--radius/--spacing`不能用于导出JSON。

### 估时、确认与进度

选中多于1条时：先显示数量和点数，再明确告知进行最多3条小/中/大点数分层试算，每条最多5秒（若逐条时限更低则采用更低值）；两条任务只试一条。试算不生成结果文件，快速几何失败不用于正常耗时估计。根据实测给剩余耗时**估计区间，不是保证**；超时或无有效样本则明确无法可靠估计，并给逐条时限合计上界。

随后提示 `继续处理并发布整批结果？[Yes/No，默认No]`：仅Yes/y继续；No/n、空输入或EOF取消。非交互调用也必须从stdin明确提供确认，没有默认批准或静默`--yes`。No之后不执行剩余路线、不输出结果JSON、不创建报告；已经完成的少量试算不会“撤销”，也不会发布。Yes后复用有效试算结果，按源顺序返回整批。

估时、提示和进度写**stderr**，stdout只有最终JSON。终端显示进度条、已完成/总数、当前index与ID、耗时和动态剩余估计；非终端写按行日志，长任务定期心跳。ID按终端安全转义显示，避免控制字符。每条在同脚本子进程中串行运行，默认60秒时限（含启动），可用 `--route-timeout 120` 修改（0.1–3600秒）；worker仅接收坐标及可选海拔，不传递段描述或点元数据。请求通过自动关闭的匿名临时文件作为stdin，避免Windows同步管道写入阻塞超时/心跳循环；临时文件不作为用户报告保存。超时回收worker，记录该条类别1后继续。Ctrl+C回收当前worker并退出，不发布假完整报告。不启动网页、不产生临时GPX、不引入tqdm或第四个依赖。

### 结果、安全与退出码

JSON导出模式默认只返回按源顺序排列的ID/类别配对，例如：
```json
[
  {"topRouteId": "tktrk956", "category": 1},
  {"topRouteId": "example-id", "category": 2}
]
```
`category`只有1/2/3/4，不附配置、几何指标和批次元数据。使用数组而非ID字典，避免重复ID覆盖结果；缺失ID显示null，记录不丢失。输入No等取消行为、估时和stderr进度不变。

需要诊断时显式添加 `--detailed`，才返回 `kind=route_shape_batch` 完整envelope，含来源内容SHA-256、实际格式、选择、总数、处理数、耗时、各类别计数和 `results`；每项保留1基 `source_index`、NDJSON物理 `source_line`、`topRouteId`、warning及完整 `classification`。Python `run_export_batch()`仍返回完整结构，`compact_batch_results()`可提取配对。单条几何错误不会吞掉其他路线；默认简洁输出和详细输出都不包含用户名、描述、地址或坐标。GPX原有输出不变，`--detailed`仅适用于导出JSON模式。

| 退出码 | 含义 |
|---|---|
| 0 | 批次完成且全部为2/3/4 |
| 2 | 完成但含类别1（仍有结果），或输入/选择/输出失败（不发布批次） |
| 3 | 用户No、空输入或EOF取消，无报告 |
| 130 | Ctrl+C中断，无完整报告 |

扫描上限256MiB/10000记录，单JSON文档上限64MiB，单路线/NDJSON行16MiB。NDJSON逐行索引offset与记录哈希，不常驻全部坐标；单文档数组有界解析。拒绝重复对象字段、NaN/Infinity、无效编码和过深JSON，不容忍破损行后偷偷跳过。逐路线继承50,000点及原分类几何预算。源文件扫描后身份、时间戳或内容变化会停止；执行结束核验完整文件哈希，避免混用版本。

`--out`在任何试算前预检已有文件和父目录；报告先写入同目录独占临时文件，写完后用不覆盖的硬链接原子发布，最后清理临时名称。不覆盖输入或竞争创建的文件，失败清理也不删除结果路径上其他进程创建的文件。目标文件系统须支持硬链接（本机NTFS已验证），不支持则报输出错误而不降级为覆盖写入。父目录必须存在；stdout模式不写报告。`elapsed_seconds`不把用户等待确认的时间混入执行估计，另提供包含确认的wall时间。进程时限不是硬内存隔离，估计仍可能受复杂几何、磁盘和系统负载影响。

自包含适配/确认/生命周期测试在 `tests/test_json_route_batch.py`，复制脚本独立运行的真实Yes/No子进程测试在 `tests/test_standalone_recognition.py`。私有导出不提交仓库。

## P0 已落地范围

- 网页默认仅分析，候选未确认前只提供 JSON 分析报告，不发布转换 GPX/GeoJSON。候选预览不代表已保存结果。
- 现有尾巴/重复圈算法被封装为 `route_plans.analyze()` 候选生成器，`route_plans.apply()` 重新核验输入 SHA-256、完整分析、处理目标、计划摘要与严格布尔确认；主体环额外要求同意删除接入行程。已阻止候选不能确认转换。
- HTTP `POST /api/analyze` 与 `/api/apply` 分离；旧 `/api/run` 为仅分析别名。确认后生成 GPX、GeoJSON、报告、manifest；服务端临时目录准备完成后才原子发布并注册下载。

下文 `route_dedupe.py` / `run()` 保留为 legacy 基线和兼容入口，直接调用仍会裁切并输出 `cleaned.gpx`、`cleaned.geojson`、`comparison.png`、`report.json`，**不经过网页确认保护**。不要将它作为 P0 安全执行 API。

## 算法

1. `xml.etree.ElementTree` 读取 GPX (优先读取单段 `trkseg`，无轨迹段时支持单条 `rte`，至少 3 个点)；采用 UTM 本地投影以米计算。
2. 每 10 米重新采样，在全程前 45% 和后 45% 中用 `cKDTree` 搜索空间近邻。可通过 `Config.max_tail_m` 额外限制每侧搜索距离，默认不设绝对距离上限。
3. 结合距离、反向航向和局部沿程单调匹配寻找持续重合，允许重合晚于起点出现、两侧接入行程不等。默认重合至少 150m，连续段匹配密度至少 85%，且匹配长度至少覆盖每侧待裁行程的 70%。这些是几何启发式，不是道路身份或交叉安全保证。
4. 符合条件后保留中间主体闭环，**裁掉两侧整个接入行程，包括未匹配部分**，不是只删一次重复通过，也不保证保留全部唯一路段。切点间距不超过 20m 才允许中点闭合。
5. 未发现尾巴时，检测 2–6 圈同方向、完整、近似等长的全线周期匹配。默认单圈至少 450m，因此标准 400m 跑道重复圈不在默认支持范围。
6. 没有满足规则时保持原样，不代表不存在重叠；内部回头支路没有专用处理。近似对称纯往返有保留保护，但没有“自动保留单程”能力。

### 本机样本与效果边界

`34044834.gpx` 的先前实测：46.204km / 1044 点 → 44.166km / 1008 点，首尾切点约 16m 偏差以中点拼接。这只是单个样本，不是普遍去重准确率，也不是道路导航级地图匹配。

`37002172.gpx` 暴露了旧规则的问题：从起点开始的短暂不匹配、2.5km 搜索上限和两侧路程对称要求，都会阻断后续持续重合的识别。现在用局部连续匹配与覆盖率约束处理此结构。报告中的 `prefix_matched_m` 是一侧匹配长度估计，`unmatched_access_m` 是两侧被裁行程中缺少反向匹配证据的长度估计，不能当成已验证的独有道路长度。

### 回归覆盖

`tests/test_route_dedupe.py` 包含原有检测器检查，以及完整处理与导出检查：长尾巴、较晚开始且两侧不等长的接入行程、单圈、2 圈、开放路线、纯往返、8 字、半径外平行道路、过短重合、覆盖率不足、切点超限。可选真实样本测试需要 `examples/37002172.gpx`，缺少私有文件时跳过。合成测试通过不代表任意 GPS 漂移、立交或路网拓扑均已验证。

### 已知限制

- 不支持把任意多分叉、多次交叉或重叠支路拆成无重复道路图；该问题需要独立的路段级匹配、交点切分与图重构模块。
- 不能跨越单个 GPX 的多个轨迹段：直接合并可能跨越轨迹中断、产生虚构道路。
- 缺少道路平行线和道路等级语义，约 10–20m 的 GPS 近邻可能是不同物理道路。导航前需对接地图匹配/路网校验。
- 一次标准闭环不应该被删除。重复整圈判定只在全线近似周期重复时启动。
- 处理后的 GPX 不保留原始时间戳（裁剪、重定位后原始时间语义不再成立）；可保留原有海拔。
- 压缩长度指实际运动轨迹长度减少，不代表删去了 2km 独有的道路几何。

## 路线拓扑、处理目标与成功比例

完整的逐类说明见本地 `/about`：包含 12 类结构、识别依据、难点、当前行为与处理前后示意。结构可以叠加，不是软件已经实现的 12 个分类器。

| 结构 | 识别依据与难点 | 当前 / 规划处理及前后对比 |
|---|---|---|
| 开放单程 | 端点分离容易检查，不代表内部无重复 | 当前无规则命中则 `A→B→C` 不变 |
| 简单闭环 | 闭合不等于简单环，需要排查重复边 | 当前普通 `A→B→C→A` 保留 |
| 纯往返 | 折返点两侧反向对齐，噪声会破坏对称 | 当前尝试安全保留 `A→B→A`；规划取 `A→B`，会改变终点 |
| 尾巴＋环 | 首尾持续反向重合、覆盖率充分 | 当前 `S→A→环→A→S` 变成 `A→环→A`，接入道路被移除 |
| 不等长接入＋环 | 重合开始较晚，局部进度一致但整体不对称 | 当前覆盖率达标可取中间环；未匹配接入也可能一起被裁 |
| 完整同向重复圈 | 2–6 个近似等长周期、相位坐标一致 | 当前 `环×k` 目标变成一圈；圈数可能误计，标准 400 米不在支持范围 |
| 残圈 / 混向圈 | 固定周期假设失效，需要局部对齐分段 | 专用处理未实现；规划分别保留完整环和残段，不保证当前原样 |
| 内部回头支路 | 任意位置持续反向匹配，区分支路与真环 | 规划 `A→B→C→B→D` 取 `A→B→D` 或保留 AB、BC、BD 道路图；当前未去重 |
| 8 字 / 相接双环 | 交点需验证为真实路口，不能把点交叉当重复边 | 当前有保留样本；规划保留双环、分环导出或按目标选主环 |
| 共享走廊 / 多分叉 | 边聚类、交点切分、通过次数；存在多解 | 规划分别输出连续主路线与完整唯一路网，当前未实现 |
| 平行路 / 立交 | 几何近邻不足以证明同一道路，需要路网语义 | 安全目标是保留不同道路；当前可能误裁 |
| 断点 / 多段 / 漂移 | 先检查段边界和数据质量，不能虚构连接 | 多 trkseg 当前拒绝；单段异常点清洗与分段处理未实现 |

主环提取、单程保留、全部唯一边覆盖、连续可导航路线是不同目标。比如树形支路要走到尽头再回来，重复通常不可避免；不能同时保证全覆盖、闭合、绝不重边。当前仅提供两类几何裁剪候选；P0 已增加与候选对应的主体环/一圈目标选择和确认，但没有通用多目标规划或路网重构。
