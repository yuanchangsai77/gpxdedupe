# 成都全量密度筛选与路线表达

## 当前规则

读取全部42130条原始轨迹，按距离加权统计5×5公里等面积网格。不同路线数≤10条/格暂定为低密度，超过10为高密度。网格内同一路线往返只计一条；另存累计长度密度，往返、跑圈按长度正常贡献。名称“密度”描述库内轨迹分布，不代表独立用户数或真实人流量。

每条路线默认只选择一种完整几何，不分段拼接：

1. 原始统计长度为零或存在被排除的大间隔时待复核，不自动展示。
2. 至少20%长度处于低密度格，且低密度长度至少500米时，优先整条原始轨迹。全程不足500米的短路线要求全程位于低密度格。即使有可靠重建，也优先原始。
3. 其余路线采用已有candidate状态且有几何的重建结果。review不作为已通过，重建失败不自动进入默认集合。
4. 最后执行高密度空网格补充，规则见下一节。未入选记录仅降低默认展示优先级，不删除，不判断语义重复。

10条/格、20%和500米均为可调的实验参数，尚未通过人工标注确定最优值。跨区路线按低密度长度比例判断，不按起点或行政区归属。例如3637全长148.8公里，其中50.5公里、33.9%位于低密度格，保留整条原始。其重建失败有明确路网越界记录，不应归因于路线长。

## 高密度空网格补充原始路线

先完成上述低密度原始、高密度重建常规选择，再检查每个高密度格是否至少有一条已选路线的原始证据经过。

- 没有已选路线经过的高密度格作为补充目标。
- 只从基础质量通过且尚未选中的原始路线中寻找候选。
- 按候选对空格的格内长度贡献排序，每格评分上限5000米，防止反复跑圈主导排序，平分时按编号确定顺序。
- 逐条检查尚未被补上的格。候选对这些格的新增长度须≥500米；不足500米的短路线须贡献全长，才保留整条原始。
- 每选一条就更新空格集合，避免为已经补上的区域重复添加路线。候选顺序固定，是保守的覆盖启发式，不保证全局最少路线数。
- 没有足够证据时允许保留空格，不伪造路线，不调用规划器兜底。

**这里只检查5公里区域是否有已选路线，不是逐条道路的覆盖检查。** 重建路线使用原始走廊关联格作近似，不能证明规划几何覆盖了该格全部道路。补充原始不代表现实通行、合法或安全认证。

全量默认结果：4900条重建＋470条原始，共5370条；470条中54条为高密度空格补充，另有12条已有重建改为优先原始。高密度空格118→0。36759条降低默认优先级，1条基础观测待复核。没有删除源证据或重建结果。

## 统计实现与产物

coverage.py使用标准纬线30度的球面等面积圆柱投影；对相邻GPS观测以不超过20米的间隔作中点积分，每样本代表一段实际长度，避免采样频率影响。超过1000米的观测间隔不跨接，累计排除长度并转待复核；这也可能影响真实低频采样轨迹。coverage_fast.py以4096观测区间分块向量化实现相同积分，测试验证长度守恒和数值一致。

coverage_rollup.py可从对齐的细网格汇总大网格；路线数按路线重新去重，不直接累加小格路线数。全量任务直接统计5000米尺度，避免构建不需要的细网格。

独立覆盖库保存routes、contributions、cells及贡献视图：路线格内长度/格内总长度为路线对网格贡献，路线格内长度/全程统计长度为网格对路线贡献。密度不随展示集合变化。

- outputs/chengdu-city/coverage/full.sqlite3：全量索引、默认density_decisions及报告元数据。
- full.report.json、full.report-v2.json、policy-v2.json：当前默认规则、多档阈值和逐路线决定。
- full.report-v1.json、metadata.density_report_v1：优化前基线报告。
- index.html、full.html：当前全量展示，sample-3000.html保存原顺序样本页。
- 源码results/chengdu-density-delivery.json：小体积全量实验摘要，不包含GPS几何或数据库。

## 执行

在gpx_dedupe_project下串行运行，不允许并发写覆盖库，原始库应保持固定快照：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 -m route_semantics.density_batch --source outputs/chengdu-city/city.sqlite3 --output outputs/chengdu-city/coverage/full.sqlite3
python3 -m route_semantics.coverage_view --source outputs/chengdu-city/city.sqlite3 --coverage outputs/chengdu-city/coverage/full.sqlite3 --output outputs/chengdu-city/coverage/full.html
node route_semantics/density_refresh.cjs outputs/chengdu-city/coverage/full.html outputs/chengdu-city/coverage/policy-v2.json
```

density_batch限制单CPU及2GiB地址空间，按路线事务续跑并检查源摘要。它保存初步偏好选择；空格补充最终规则以density_policy.js为准，网页和density_refresh共用该实现。density_refresh输出最终逐条结果；本次已同步到独立库density_decisions和报告。重跑后不能将density_batch初步结果当作含补充规则的最终结果。

历史小样本入口coverage --limit N按源ID升序取前N条，**不是随机抽样**；支持扩展，不允许降低已有索引范围。扩库后需重新派生网格、筛选与导出。coverage.select/shortlist以及coverage_selection.py的100米覆盖贪心是旧实验基线，不用于当前全量密度规则。

## 页面与验证

页面保留布局、路线选择、格内双向贡献、鼠标位置缩放和拖动。默认“低密度原始＋高密度重建”；全部原始可查看被隐藏记录；覆盖代表原始/混合跟随全量页当前阈值。默认界限10，支持对比2/5/10/20/40/80，切换累计长度时单位变为公里/平方公里。紫色重建、蓝灰原始，绿色低密度、橙色高密度。密度始终基于所有原始。原始总览使用既有简化几何及5位小数；重建路线展示使用完整存储的道路几何并保留6位小数，避免80米概览采样在公园弯道产生直线截弯。统计和原始证据不改变。底图与既有页使用相同坐标转换，无付费规划请求。

全量统计676.48秒，统计加初步筛选731.14秒，不含后续表达优化和页面导出；1305个有覆盖的5公里格。全量网格不同路线数中位数20，上四分位67。没有单独测量表达优化耗时，不能把12分钟说成包含整个交付。

已验证8项Python单元测试、JS策略测试、Ruff、Node语法检查和42130条真实页面浏览器检查；数据库quick_check及累计长度守恒通过。尚未完成：完整漂移/速度质量模型、独立来源抵扣、人工准确率标注、网格边界平移敏感性和道路级覆盖评估。内嵌全量页面能用于本地实验，生产App应按视窗与缩放级别加载，不直接复用全量内嵌数据方式。当前没有路线去重。
