一、当前实现和测试结果

3.1 已实现基线

算法为 Python + NumPy / SciPy cKDTree + pyproj；用局部 UTM 投影、10 米等弧长采样及方向约束匹配。当前只接受一个 trkseg，至少三个点。先尝试首尾连续反向匹配的主体环裁切，再尝试 2–6 圈完整近似等长的同向重复圈。

本地网页已有文件夹列表、文件搜索、半径设置、并排/叠加、同步缩放平移、坐标检查、主题和 GPX / GeoJSON / JSON 下载。HTTP 服务绑定回环地址，源文件只读，每次运行独立输出。导出不保留原时间戳。现有 HTTP 请求同步处理，算法运行由锁串行化；尚无持久作业队列、进程内存上限或通用拓扑图。

3.2 可复现的合成基线

352 个样本由 44 个几何变体 × 4 档坐标噪声 × 2 个种子构成。噪声为逐观测点独立的 x/y 高斯扰动，σ = 0、1、3、8 米。零噪声的两个种子是重复对照，不是两个独立事实；所有样本也不是独立真实路线。表中分母均为指定样本族，不能外推到线上成功概率。

3.3 实例能证明什么

一个本地问题样本经修复后，行程约从 58.021 km 缩为 49.166 km，减少 8.856 km；单侧连续反向匹配约 3.310 km，所裁首尾行程中约 2.241 km 没有反向匹配证据。这证明该样本的主体环裁切已触发，不证明减少的全部长度都是重复道路，也不证明保留了全部独有道路。本文不附私有坐标、源目录和原始文件。

3.4 必须优先解决的缺口

  1. 几何近邻导致平行路误合并；纯往返在噪声下可能被当成尾巴 + 环。
  2. 圈检测依赖整段等分，默认单圈最小 450 米；短圈、残圈、方向切换无可靠支持。
  3. 仅两类整体裁切启发式，缺少内部重复、多分叉、组合拓扑和冲突关系。
  4. 没有真实标注集和概率校准；70%、85% 等规则是阈值，不是成功概率。
  5. 文件字节上限不能约束候选数量、计算时间和内存；overlap_stats 仍存在密集点对增长风险。

二、问题与具体方案

不再把整条路线直接分成固定类型并裁切。先找出重叠区间及其通行方向，再组合成往返、环、支路等结构；根据目标生成保留或删除计划，最后验证输出是否连续、是否丢失独有路段。

三、轨迹、拓扑与通行模型

几何是坐标；拓扑是连接关系；通行序列是用户按时间或点序走过哪些边、走过几次及方向。三者必须分开建模。一个轨迹可以同时包含尾巴、多个环和内部支路，不使用互斥的 12 分类标签强行归类。

  • 原始轨迹 T：保留原点索引、段 ID、经纬度和可用的时间/高程；不跨段建立默认连接。
  • 匹配假设 H：两个弧长区间的候选对应，包含同/反向、距离分布、覆盖、单调性、备选匹配及冲突。
  • 观测图 G：节点是经证据支持的连接位置；边代表候选道路片段，采用多重图保留平行边；空间交叉先是候选而非自动路口。
  • 通行序列 W：按原顺序记录 edge_id、方向、原始区间和重复次数；与“只存每条边一次”的图分离。
  • 处理计划 P：绑定目的、保留/删除区间、边界修整、必要重复与用户决策。执行器只执行通过验证的计划。

不可同时满足的条件：在连通无向图中，每条边恰好一次的单条行程要求奇度节点为 0 或 2；要求闭合时必须为 0。树枝去到端点再返回必然重复。单行、转向限制或图不连通会增加约束，不能仅靠欧拉条件就宣称可导航。

本方案在没有地图证据时输出的是观测几何图，不是已确认的真实道路网络。即使有地图匹配，数据缺漏、时效和法规也使“已做道路约束校验”不等于保证现场安全可通行。

五、模块划分与处理流程

保持现有本地工作台，逐步将算法拆成独立可测试模块；不为本地单用户场景引入微服务、云数据库或默认在线服务。采用本地 API + SQLite 作业状态 + 隔离算法进程 + 文件制品库。

  1. 导入与快照：复用源路径安全检查，创建有界只读快照和 SHA-256；入库作业只保存受控文件标识，不向浏览器暴露任意输出路径。
  2. 质量与归一化：验证坐标、段数、点数和跨度；建立原始点到弧长采样点的映射，不修改原始数据。
  3. 候选匹配：空间检索 + 有序区间对齐，产出证据与冲突，受全局预算限制。
  4. 拓扑分析：从可靠对应建立观测多重图和通行序列，组合识别往返、环、支路等 motif。
  5. 计划生成：依据用户目标枚举有限候选，计算独有覆盖代价、连续性与规则冲突；不能满足时返回原因。
  6. 预览与确认：用户按候选范围接受/拒绝；决策绑定输入、配置、候选版本。
  7. 验证与导出：独立验证器检查不变量，原子发布制品，输出 manifest 与审计报告。

六、算法实现

7.1 输入质量与多尺度采样

  • 保留原始坐标作为事实层；重复点、跳点、缺失字段仅作标记。需要去噪时生成辅助表示，并记录参数和变更量。
  • 首期沿用单段输入约束，新增多段感知但不跨段匹配/连接；完整多段处理单独验收。
  • 局部投影仅用于适合的区域跨度；跨日期变更线、极区、大跨度路线先拒绝转换或进入经专项验证的分块测地模式，不继续套用单一 UTM。
  • 粗尺度用于发现候选、细尺度确认边界。采样间隔和最短重复长度分离配置；短圈模式另建 400 米以下对照，不能简单把全部门槛调低。
  • 方向在弧长窗口内估计；停止/转折附近标记低可靠方向，不能用单点切向量强行过滤。

7.2 有序路段匹配，而非孤立近邻

  1. 对空间块或线段包围盒建立索引，按批次检索可能相近的轨迹区间；排除紧邻采样造成的自然相近。
  2. 按同向/反向分别形成匹配种子，保持两个弧长参数近似单调；使用有带宽、长度和候选预算限制的动态规划/局部序列对齐。
  3. 验证横向偏差、p50/p90 距离、双向覆盖、缺口分布、方向一致性、序列拉伸和匹配唯一性；必要时用带界的离散 Fréchet 检查候选，避免对全轨迹做全矩阵。
  4. 比较最优与次优候选并保留冲突；不能把沿路缓慢漂移与邻近的另一条路可靠区分时，标记道路身份未知。
  5. 输出不超过预算的候选集合及截断状态。预算耗尽返回 analysis_incomplete，禁止依赖残缺候选作自动删除。

距离、方向、覆盖等首先是证据字段，不是置信概率。可显示“证据充分 / 有歧义 / 不足”的规则状态并解释原因；在真实留出集上校准前，不显示“成功率 95%”。

7.3 噪声与平行路的特殊防护

不通过持续扩大半径“治好”噪声，因为这会扩大误合并。精度字段（如存在）可用于提示不确定范围，但不是道路身份凭证。稳定横向分离、两端不同连接、竞争匹配或缺失道路证据时，不自动合并。高程仅作辅证，不能单独确认桥隧。若误差范围已覆盖两条可能的路，算法应承认不可辨。

7.4 观测图构建与连接确认

仅在匹配边界、明确通行衔接和经证据支持的接点处切分。Shapely 的二维交点只能生成候选；不因投影线交叉就建立可通行路口。NetworkX MultiGraph 可用于保留平行边、求连通分量和检查度数，但图工具本身不会识别真实道路。

合并优先采用可追溯的代表观测几何，不对两侧平行道路直接取均值。聚类必须检查簇内一致性，防止 A 接近 B、B 接近 C 就把相距较远的 A/C 传递合并。图上每条边可回溯到所有原始通行区间。

7.5 重复圈与组合 motif

  • 重复圈：用返回同一锚点的事件和区间匹配提出周期，允许圈速/采样密度不同；验证最小基本周期而非只接受一个能整除总长的大周期。
  • 纯往返与尾巴 + 环：分别验证转折后的反向路径，以及保留中段是否包含真实的非退化环证据。仅“裁后首尾很近”不足以认定有环。
  • 残圈/混向：先分出闭合子行程，剩余片段独立展示；同向和反向通行分组，不用总长等分强行解释。
  • 内部支路：识别离开/返回同接点的反向链，再验证移除后主行程连续；明确其独有覆盖损失。
  • 组合结构：motif 可嵌套或共享边；冲突计划互斥。限制候选计划数，不进行任意子集指数级穷举。

7.6 按目标规划

主体环先枚举少量有证据的闭合子行程，按独有覆盖、连续性和用户指定起终点排序，不能默认为面积最大。单程保留完整去程或返程之一，不通过删掉两端凑闭环。一圈优先保留一个真实完整观测圈，保留时间元数据的原始关联但不伪造新的运动时间线。

唯一路段模式输出多重图与分段线集合。连续行程模式先尝试保留原始通行顺序的可验证简化；后续才在明确无向、连通且无转向约束的子问题上采用开放/闭合邮差路线算法。缺少方向/通行规则时不能把该解标为导航路线；有向及受限问题超出首期范围。

7.7 可选地图匹配

只有用户单独同意后，才接入本地 OSM 数据或指定 GraphHopper 等引擎；优先本地运行。保存地图快照日期、引擎版本、交通方式、候选与偏离，不把强制吸附结果当成真值。在线调用须列明服务商、发送范围、缓存和日志策略；没有授权时绝不发送坐标。地图匹配失败不能退化为静默几何合并。

七、转换约束与结果校验

8.1 三类决策，不混淆“拒绝”与“失败”

状态进入条件允许动作
可预览候选分析完整、证据与几何约束通过、无未决冲突展示候选；首发仍需用户确认才导出转换结果
需要人工核对多个候选、可能不同路、拟删除独有接入或内部支路显示疑点及代价；允许目标性裁切，但不把歧义登记成已证实道路相同
禁止转换 / 分析不完整超限、无效输入、缺口无法接续、关键验证失败保留原始文件；返回原因与可采取动作，不能用普通确认绕过硬约束

8.2 执行前后不变量

  • 不改源：输入快照哈希一致；源文件不写入。计划所引用的输入、参数或分析版本变化即失效。
  • 可溯源：每段输出指向原轨迹区间；任何新增连接与边界修整必须独立记录。无法解释的点或线段禁止导出。
  • 不跨缺口：距离小不代表有路。优先在已验证匹配区间选择共同切点；首期不自动补未知连接。手工允许的连接仍标“未验证”，不得计为已有道路。
  • 按目标守覆盖：保留唯一路段模式的独有覆盖损失必须为 0；主体环/删枝模式的损失必须与明确选择的区间一致。
  • 不虚报闭合：端点近似闭合与真实连接分开；不通过无说明的中点吸附将开放路线变成“已验证闭环”。
  • 失败封闭：验证失败不发布成功制品、不留下可下载的半文件；保留失败原因与受控诊断，不泄漏源路径。

8.3 长度与影响口径

报告分开统计：输入/输出行程长度、经匹配支持的重复通行删除量、目标性删除的独有/未证实重复行程、新增连接长度、边界修整的长度变化及未分类差额。要求在容差内对账。唯一图的边覆盖长度另算，不能与行程长度混用。空间容差覆盖率只是几何指标，不是道路身份真值。

九、页面交互与结果展示

  1. 选文件：保留本地目录与文件过滤；显示输入能力限制和原始字段。
  2. 选目的：默认“仅分析”；每个模式用一句话说明允许删除什么、是否保证闭合。
  3. 看结构：展示可组合的 motif、证据范围与分析完整性；未知结构也可正常显示，不硬给标签。
  4. 看候选：沿原始弧长定位，分别标出保留、删除、未匹配删除、疑似平行路和连接；线型/文字与颜色共同编码。
  5. 核对代价：显示独有覆盖变化、起终点变化、是否丢失残圈/分支、是否还存在必要重复。
  6. 确认导出：计划摘要与输入绑定；风险区间必须可定位。验证通过后才出现转换下载链接。

失败文案区分“未发现候选”“存在歧义”“超出计算预算”“几何接续不成立”和“道路规则未核验”。不把 unchanged 写成“识别成功，无重复”；不将人工接受写成“算法证实道路相同”。首发不新增需要外网底图的依赖。

十、资源控制与本地运行

11.1 现有与新增限制

已实现：16 KiB 请求体、50 MiB GPX、目录最多返回 2,000 项；路径重检、符号链接/目录联接拒绝、DTD/实体声明拒绝、有效有限经纬度校验、Host/Origin 检查、受控下载。现代码可能在等待运行锁前读取文件快照，因此算法串行不代表并发请求的内存受控。

以下是第一轮压测起点，未验证为可达性能。限制必须配置化，发布前按实际机器校准，不把 50 MiB 可读等同于 50 MiB 可分析。

资源初始预算（待压测）超限策略
并发与排队1 个算法 worker；最多 4 个待执行作业先获取准入再读快照；队满返回 429，提示重试

Windows 优先使用 Job Object 对整个进程树施加内存与退出约束；Linux 使用可用的 cgroup 等机制。不能建立或实测隔离时，不宣称资源硬上限成立，也不开放高成本转换。取消、超限、异常退出都要有集成测试。SQLite 作业状态与制品先写临时目录，再原子 rename 与登记，防止半成品可见。

11.2 本地服务加固

继续只绑定回环地址；新增同源页面的会话级请求令牌用于创建/取消/确认/导出，并校验 Origin 与 Host。会话令牌不是公网身份认证；若未来支持远程访问，必须另外实现 TLS、认证、权限、配额和审计，不能只修改监听地址。

源文件名单、作业、下载记录与临时目录有数量和周期上限。重启后凭受控 manifest 恢复下载注册，不从用户提交的路径恢复。日志默认只含哈希截断标识、阶段、耗时和错误码，不含坐标、个人目录或轨迹正文；调试采集需显式同意。

11.3 隐私与供应链

真实数据和截图保持本机，不提交仓库；共享评测优先使用经许可的合成或脱敏样本。依赖固定版本并检查许可证与漏洞。OSM 数据和引擎的授权、归属声明、分发要求在接入前单独核查。默认关闭遥测、在线底图及地图 API，外部服务不可成为离线模式的隐含依赖。

十一、测试数据与指标

12.1 标注对象与数据分层

真实集同时标注：重复区间及方向、候选道路身份与不确定性、实际连接、组合 motif、每个处理目标的可接受输出集合、独有路段和禁止删除区间。没有足够证据的道路身份应标“未知”，不能由待测算法自己生成真值。两名标注者独立标注，分歧仲裁并报告一致性。

先建 100 条独立路线的探索集形成标注手册；发布验证以至少 300 条独立、可判定且符合支持条件的留出路线为起点，另设平行路/立交/往返等困难负例集。按同一物理路线/同一次出行的来源组分割开发与留出集，扰动、截段、重复采样不得跨集合；每个要宣称支持的关键类型至少 30 条独立路线，不足则缩小支持声明，不用总体平均掩盖。

地图辅助版本与纯 GPX 版本分开评估，未知样本单列；对算法的拒绝保留为有效结果。真实道路标签需要现场、可靠地图或其他独立证据；真实标注不充分的集合只能评估几何任务。

12.3 阶段门槛

  • 硬约束：源文件改写、未授权外传、未登记补线、硬约束失败仍成功导出均为零容忍；任一出现即阻断发布。
  • 已知误裁回归：当前纯往返 9 个误裁和 10 米平行路 8 个误裁必须全部改为正确处理或明确歧义保留；不要求用错误的强分类来“通过”。
  • 合成转换：在当前完整同向圈、等长尾巴、不等长接入三族的 168 个样本上，正确转换目标分别不低于 90%；每档噪声单列。400 米圈若未达到独立门槛继续列为不支持，不能混进长圈平均值。
  • 真实条件正确率：对已声明支持、系统判为可转换的候选，目标点估计 ≥98%；同时报告 95% 置信区间。该数字是验收目标，不是当前表现。
  • 可转换覆盖：在真值可处理的简单长圈/尾巴路线中目标 ≥70%，各型单列；以安全为前提，不为达覆盖而放宽道路身份约束。
  • 误删统计：若希望声明路线级未授权误删率的单侧 95% 上界 <1%，需至少 300 条独立转换路线且观测为 0 次（精确二项近似上界约 0.995%）。300 条“输入路线”中大量拒绝不满足该样本量；有误删时须重新计算上界，不套用零事件公式。
  • 资源：在已冻结的支持配置内不得突破预算而继续运行；超时/内存/取消路径全部可测。是否能在 120 秒、512 MiB 内完成目标规模须压测决定，不作为已达成承诺。

当前 352 个合成样本重复且非独立，不对其套用真实路线二项置信结论。真实评测采用来源组为独立单位；存在相关性时按路线组做 bootstrap 或更保守统计。阈值调整后不能反复以同一留出集宣称独立验证，需新冻结测试集。

12.4 测试层次

  1. 单元/性质：反转不改变无向覆盖、插密不改变拓扑、重复一次圈数按预期变化、平移旋转在容差内不改结果、源数据不变。
  2. 回归：现有 37 个单元/HTTP 测试与 352 样本；新建短圈、密集停留、桥隧、断段、混向和复杂组合族。
  3. 端到端：文件选择 → 分析 → 决策 → 导出 → 重新解析 → 独立验证，含移动端、深浅主题和无外网检查。
  4. 故障：磁盘满、路径变化、并发准入、取消、进程被杀、服务重启、超限、畸形 XML、版本冲突和失败目录清理。
  5. 真实盲测：冻结配置与目标后一次性评估；保留失败样本及失败分类，不只展示成功路线。

十二、实现顺序

按测试结果推进，不在缺少人员与硬件信息时承诺工期。每阶段通过对应测试后再启用下一阶段。完成探索与资源压测后再估人日和排期。
